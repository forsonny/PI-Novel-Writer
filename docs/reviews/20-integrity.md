# Change 20: dependency freshness and execution integrity

Review found three integration risks: a changed source could leave an indirect review apparently current; a later belief could suppress an earlier belief before its cutoff; and independent extension instances could run the same asynchronous scene job together. Source freshness now traverses the dependency graph with bounded cycle checks, acceptance verifies every new artifact's dependencies, and memory selection applies the temporal boundary before supersession. State chains cannot supersede unrelated or unavailable records. A per-job lease spans model execution without holding the canonical-store write lock. Recovery requires an explicit author command, an unchanged token and a dead local owner; a remote owner is never guessed dead.

Continuation also preserves the exact existing whitespace rather than trimming earlier prose. Five new tests cover these cases, live-lock refusal and cleanup. `npm run check` passes: syntax, strict TypeScript and 95 tests. These are engineering fixtures, not literary efficacy measurements. Protection against malicious simultaneous directory replacement is still an OS sandbox responsibility. Dead-owner recovery does not refund an interrupted model-call reservation.
