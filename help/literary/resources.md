# Records and schemas

Runtime schemas are available through `novel_literary_schema`; exported JSON files
are in `schemas/`. The TypeBox source is authoritative for structural versions,
while domain validators enforce evidence, chronology, dependencies and authority.

Private `.pnw` data includes content-addressed objects, accepted snapshots, a HEAD
pointer, migration backups and job/call journals. Each acceptance records source
versions; a stale dependency requests reassessment without deleting earlier prose.
The package does not encrypt the disk or control a provider's retention policy.
Use appropriate local storage and transmission permissions for unpublished work.

`novel_literary_memory` reads coordinator records, not a guarantee that every
character knows them. `novel_literary_patterns` provides versioned pattern cards
and scope-specific repair risks, not a provenance detector.
`novel_literary_resources` counts worker reservations and known usage; unknown
costs are null, not free. Host/coordinator/compaction usage is outside that subtotal.

Accepted export includes a private source manifest; Git publication rejects
private paths and requires a content-bound preview. Never upload reader decoding
keys or private run logs as ordinary manuscript files. Offline comparison and
reader-packet preparation are described in `protocols/evaluation.md`.
